R.S. Top Team

Um sistema de gestão criado para reunir alunos, professores, turmas, eventos, graduações, presenças e financeiro em um ambiente único para uma academia.

01 / Que problema o sistema tenta resolver?

A proposta nasceu da necessidade de concentrar a rotina de uma academia em um sistema só. Em vez de separar cadastro de alunos, chamadas, eventos, graduações e financeiro em vários lugares, o projeto organiza essas áreas em módulos conectados.

O sistema também diferencia responsabilidades: administrador, gestor, professor e aluno possuem necessidades distintas, então a interface e as permissões são pensadas para limitar cada perfil ao que ele precisa acessar.

02 / Quais áreas fazem parte do R.S. Top Team?

O escopo documentado inclui dashboard, gestão de alunos, equipe, modalidades e turmas, chamadas e histórico de presença, graduações, eventos e comunicados, cobranças, despesas e relatórios financeiros.

Também existem permissões personalizadas para colaboradores, login por PIN, temas, suporte a dispositivos móveis, instalação como PWA e notificações. Como o projeto continua evoluindo, esta página descreve o que está registrado no repositório público, sem transformar itens em resultados de uso que não foram medidos.

03 / Tecnologias utilizadas

O projeto utiliza React 19 com Vite no frontend, Tailwind CSS para estilos, Framer Motion para animações, Lucide React para ícones e Recharts para gráficos. A camada de autenticação, banco de dados e hospedagem utiliza Firebase Authentication, Firestore e Firebase Hosting.

Essa combinação me permitiu praticar componentes, estados, permissões, leitura e escrita de dados e uma estrutura de aplicação mais ampla do que uma landing page comum.

04 / O que aprendi construindo o sistema?

O R.S. Top Team me colocou diante de problemas que aparecem quando um projeto cresce: diferentes níveis de acesso, módulos que compartilham dados, históricos, estados de interface e necessidade de manter a experiência consistente para perfis diferentes.

O projeto segue em desenvolvimento. O código e a versão publicada ficam disponíveis para mostrar o estado atual e permitir que as decisões técnicas sejam verificadas junto do estudo de caso.

As funcionalidades descritas aqui vêm da documentação pública do projeto. A capa do portfólio é uma composição visual e não representa, sozinha, todas as telas do sistema.
