04 / Desenvolvimento Web · SaaS

Atlas Gestão

O Atlas Gestão é uma plataforma SaaS multi-tenant em desenvolvimento para concentrar processos de academias em uma estrutura única, separando dados e permissões de cada organização.

01 / Qual problema o Atlas quer organizar?

Academias precisam lidar com informações de alunos, equipe, modalidades, turmas, chamadas, graduações, eventos e financeiro. No Atlas, a proposta é reunir esses fluxos em uma plataforma com áreas diferentes para cada perfil, sem misturar os dados de academias distintas.

O projeto funciona também como um exercício de arquitetura: além da interface, estou trabalhando em como organizar autenticação, permissões e dados para que a aplicação possa atender mais de uma academia dentro da mesma base de produto.

02 / Como funciona a arquitetura multi-tenant?

A estrutura em Firestore organiza os dados por academia em organizations/{orgId}. Dentro de cada organização ficam coleções de usuários, membros da equipe, modalidades, turmas, chamadas, presenças, eventos, faturas, pagamentos, despesas, contratos, logs e configurações.

Essa separação reduz o risco de uma academia acessar dados de outra e torna o contexto da organização ativa parte das leituras e escritas do sistema. As regras de segurança e os fluxos do frontend estão sendo refatorados para seguir esse modelo.

03 / Tecnologias e decisões de implementação

O frontend do Atlas utiliza React e o backend de dados utiliza Firebase Authentication e Firestore. O trabalho recente inclui a adaptação de contextos, hooks, serviços e páginas para usar caminhos vinculados ao identificador da organização ativa.

O projeto também mantém logs, permissões por função e históricos de presença e graduação. O objetivo não é apenas criar telas, mas aprender a lidar com regras de acesso, consistência de dados e manutenção de um sistema maior.

04 / Estado atual e próximos passos

O Atlas continua em desenvolvimento. A base multi-tenant já passou por uma refatoração importante e o build documentado no repositório foi concluído sem novos erros bloqueantes. As próximas etapas envolvem continuar refinando os módulos, a experiência do usuário, os fluxos administrativos e a documentação visual do projeto.
